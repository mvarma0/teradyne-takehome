# Measurement approach: first 30 days

**Metric: verified-answer rate**, the share of knowledge questions that get a confident, cited answer the user does not push back on. A question counts as verified when it is answered (not routed or refused), has at least one valid citation, and gets no thumbs-down, rejection or correction; guardrail-handled messages are left out of the denominator. It combines coverage (can the assistant answer?) and trust (was the answer right?), which decide whether people keep using it, and it comes straight from data the system already logs: each answer is a `messages` row (status, confidence, citation stats), pushback is the `feedback` column plus `gaps` rows of type `rejected` or `correction`, and guardrail outcomes are in `metrics`. I'd use week 1 as the baseline, then track a daily 7-day rolling rate split by source type and topic so missing content shows up where it lives. Because a rising rate could also mean people stopped giving feedback, I'd pair it with a weekly hand audit of 20 randomly sampled "verified" answers against their citations and a golden-set eval run (`/evals`) on every configuration change; a drop triggers a review of the low-confidence queue, and each resolved gap should become new or corrected source content.
